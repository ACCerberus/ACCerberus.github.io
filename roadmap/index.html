Roadmap

Where Cerberus is going, and how it got here.

Cerberus is built in numbered phases. Each one ends in a tested release, and no phase starts until the one before it passes its acceptance tests.

What's coming

The road from here.

The highlights of every phase still ahead, in the order they will be built.

Phase 12

Pane, the window server

up next

The desktop moves out of the kernel and becomes its own protected program.

  • Real window management: move, resize, stack, focus, minimise, maximise and full screen.
  • Zero-copy drawing: each window paints into its own shared buffer.
  • Eye candy: transparency, per-window opacity, shadows and rounded corners.
  • Private windows: a program sees only its own windows and its own input.
  • Permissioned capture: screenshots, recording and global shortcuts are denied by default.
  • Secure password entry: nothing else receives keys while a password box has focus.

Target: a full 1920×1080 frame with 10 windows in under 8 ms, and no work at all when nothing changed.

Phase 13

Facet and the first real apps

planned

A widget toolkit, a proper desktop shell, and the applications that make it a system you can use.

  • Facet toolkit: buttons, lists, menus, tabs, dialogs, theming and keyboard navigation.
  • Desktop shell: taskbar, launcher, notifications, wallpapers and themes.
  • Ember, Crate and Slate: a terminal with tabs, a file manager and a text editor.
  • Gauge, Dial and Tally: a system monitor, settings and a calculator.
  • Frame, Daub and Chronos: an image viewer, a paint program and a clock.
  • Warren: a small game, plus TrueType fonts across the system.

Target: power-on to a usable desktop in under 3 seconds.

Phase 14

Networking

planned

Cerberus gets online, with a network stack that runs outside the kernel.

  • Network drivers: virtio-net and e1000.
  • netd: Ethernet, ARP, IPv4, ICMP, UDP and a full TCP implementation.
  • DHCP and DNS: an address and name lookups without setup.
  • Sockets: the familiar calls, working with event queues.
  • Tools: ping, ifconfig, nslookup, fetch and netstat.
  • Firewall on by default: incoming connections are blocked, and network access is a per-app permission.

Target: a 100 MB transfer that matches by checksum. Nothing is sent at boot except DHCP.

Phase 15

Users, sandboxing and TLS

planned

Accounts, a login screen, and real boundaries between applications.

  • User accounts: passwords stored as Argon2id hashes.
  • Login and lock screen: Super+L and an idle timeout, with no auto-login.
  • No setuid programs: admin actions go through one service that asks for the password and logs it.
  • Sandboxing: a program can permanently give up network, files, or starting other programs.
  • Keyring: a password manager encrypted with a key from your login.
  • HTTPS: TLS with a certificate store, and an audit log of logins and permission decisions.

Target: one user cannot read another's files, and killing the lock screen does not unlock it.

Phase 15B

A web browser of its own

planned

Written for Cerberus, starting with simple pages.

  • HTML and CSS: a standards-following parser and a documented CSS subset, including flex basics.
  • Layout and images: text wrapping, tables, smooth scrolling, PNG, JPEG and GIF.
  • A real browser window: tabs, bookmarks, history, downloads, find in page and zoom.
  • Sandboxed tabs: a bad page can crash a tab, never the system.
  • Private by default: HTTPS first, third-party cookies off, no telemetry.
  • JavaScript: a later, separate decision.
Phase 16

Spec, the language

planned

The systems language designed alongside the OS starts compiling for it.

  • specc: the compiler, from lexer to x86-64 code and an ELF writer.
  • Standard library: text, collections, files, threads, and direct system-call bindings.
  • Tooling: a formatter, a test runner and a build tool.
  • Excellent error messages: a requirement, with the rule explained and a fix suggested.
  • Apps in Spec: at least three applications rewritten in it, one with a GUI.

Target: specc hello.spec -o hello makes a program that runs on Cerberus.

Phase 17

Running real software

planned

Enough compatibility that existing programs can be ported.

  • Shared libraries: a dynamic linker and dlopen.
  • POSIX C library: big enough to build unmodified programs such as zlib, Lua and the Tiny C Compiler.
  • Job control: pseudo-terminals, Ctrl+Z, fg and bg.
  • pkg: a package manager with signed packages and sandboxed install scripts.

Target: the Tiny C Compiler compiles and runs a C program on Cerberus itself.

Phase 18

Installer and disk encryption

planned

Cerberus leaves the ISO and lives on a disk.

  • Live installer: erase a disk, or install alongside an existing system.
  • Boot menu: Cerberus, the previous kernel, recovery, and Windows or other systems found.
  • Full-disk encryption: optional, with the key derived from a passphrase.
  • Signed updates: the previous kernel stays bootable, and it never updates on its own.
  • Recovery: a read-only rescue shell and a file-system repair tool.
  • Service manager: start order, restart policy and a sandbox per service.

Target: an interrupted update still boots.

Phase 19

Real hardware and stretch goals

stretch

Out of the virtual machine and onto real PCs.

  • USB: keyboards, mice and USB sticks.
  • Sound: Intel HD Audio and a mixing server.
  • Booting on real PCs, including installs beside Windows.
  • Kernel address randomisation and IPv6.
  • HiDPI scaling and more accessibility features.
  • Spec compiling itself, and an ARM64 port.
