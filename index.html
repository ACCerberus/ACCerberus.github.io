An operating system, written from scratch.

Cerberus is a 64-bit OS with its own kernel, its own file system, its own drivers and its own desktop. Nothing here is Linux, BSD or Windows underneath.

Why

Three goals, in this order.

01

Private and secure by design

No telemetry. Nothing leaves the machine unless you ask. Memory is never writable and executable at once, and every system-call argument is treated as hostile.

02

Fast and small

A message between two programs takes well under a microsecond. Every performance budget is measured and recorded, so a regression is visible.

03

Understandable

One small system, with a written specification and the reasoning behind every decision, all published in the docs.

What works today

A real system, from the boot sector to the window shadows.

It runs in QEMU and VirtualBox today, brings up every CPU core, and runs protected user programs. Each card is the first line of its section in the feature inventory, which lists everything.

Security and privacy

Nothing leaves the machine unless you ask.

In Cerberus, security rules are requirements with tests, not afterthoughts. Every one of them below is enforced in the current build.

0

Zero telemetry.

Cerberus collects nothing and reports nothing. No usage data, no account to sign in to, no background phone-home. Today it has no network stack at all.

Never writable and executable

No memory can be both at once. Every request for such a mapping is refused, in the kernel and in every program.

Every argument is hostile

Each system-call argument is checked. Bad pointers, lengths that wrap and unknown flags get an error, never kernel code.

Walls in the processor

SMEP, SMAP and UMIP are on wherever the CPU has them: the kernel can neither run nor casually touch program memory.

A different layout every run

A program's code, stack and mapped memory land at different addresses each time it starts.

Nothing left behind

Memory is zeroed before a program gets it, and a new disk block never shows what a deleted file left in it.

Identity that cannot be faked

A program receiving a message learns the sender's process and user from the kernel, not from the message.

Disks are not trusted

cerfs checks every field and checksums its metadata. A damaged disk gives an error, never a crash.

Attacked on every release

Fuzzers hammer the program loader, the archive reader, the file system and the system-call interface; 53 integration tests run on every build.

Real randomness

A ChaCha20 generator in the kernel, seeded from the CPU's hardware generator and interrupt timing.

Planned, and already written into the specification

Architecture

A hybrid kernel, in clear layers.

Anything that needs sub-microsecond speed or special processor instructions stays in the kernel. Everything else runs as an ordinary, protected program.

Each layer only talks to the one below it through well-defined, checked doors. The plain-language tour is in About Cerberus.

Spec

A language designed with its operating system.

Spec is the systems language planned for writing Cerberus's own programs. Compiled to native code, statically typed, no garbage collector.

  • Regions. Memory allocated in a region is freed at its closing brace.
  • Typed system calls. Part of the language, with no C layer between.
  • Capability types. A handle cannot be copied by accident or used after it is closed.
  • Checked register layouts. The compiler refuses a write to a read-only register.
